# TopLab — End-to-End Capability Audit

**Commit** `9b912c1` · ~106k LOC · Domain/Application/Infrastructure **build clean** (Presentation can't build on Linux — WPF targeting only, not a code defect).

**Headline finding:** the layer stack is real and consistently wired (no `NotImplementedException`, no `TODO`, no stubbed handlers — grep over `src/` returns only two `ConvertBack` throws in WPF converters). But **the presentation layer is a thin shell over a much smaller domain model than the reference system**, and — critically — **most persisted settings are never consumed by any PDF writer**. The two QuestPDF writers (receipt/invoice/worksheet) are real; `ReportPdfWriter` and `PatientReportPdfExporter` are hand-rolled ASCII PDF stubs that replace every Arabic glyph with `?`.

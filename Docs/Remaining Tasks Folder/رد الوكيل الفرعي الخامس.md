L4‑1 — Create a user and assign their permissions (إنشاء مستخدم جديد وتحديد صلاحياته)
Pages: 150 (intro + entry), 151 (dialog, first instance), 152 (dialog, second instance), 153 (dialog, third instance + Save), 154 (enforcement)

Business purpose. Where a lab has more than one employee and each has a defined role, the system lets you create a user per person and assign that user's working permissions — "وبالتالى تزويد من ضبط العمل وكفاءته داخل المعمل" (p.150).

Workflow.

1.
Click the User icon in the main menu bar (p.150).
2.
Click the button ( إنشاء مستخدم ) — "Create User" (p.150).
3.
The program requests the system menu password — dialog "Please Enter Your Second Password.", titled System menu password, numbered 01 (p.150, 156). Enter 123 (the factory value) or the user's own password if they have already changed it (pp.150, 156).
4.
The Create/Edit Users window opens (p.151).
5.
Click ( إضافة ) — "Add" (p.151).
6.
Enter اسم المستخدم (user name), كلمة المرور الرئيسية (main/primary password) and كلمة المرور الفرعية (secondary password) (p.151: "نقوم بكتابة إسم المستخدم وكلمة المرور الرئيسية والفرعية الخاصه به").
7.
Define the user's صلاحيات (permissions) — the 15 toggles catalogued in L4‑2 — using the fields shown on p.151.
8.
Press ( حفظ ) — "Save" (p.153).
9.
The new user appears in the user list on the left-hand side of the window (p.153, explicitly "بعد الانتهاء نضغظ ( حفظ ) ونلاحظ ظهور المستخدم فى قائمة المستخدمين على يسار النافذة").
Inputs. User name; main password; secondary password; branch number(s) (multi-select — p.153 shows 1, 2, 3); 15 permission flags; work-shift times; break flag + break duration; max discount value.

Outputs. A persisted user record shown in the left-hand user list; a log-in-capable account with exactly the permissions entered.

Business rules / validations / automatic behaviour.

Password gate is mandatory before the window opens — it is a second, system-menu-level password, not the user's login password (p.150).
The factory second password is 123, and the document explicitly states the same button accepts the user's own password if already changed (p.150) — i.e. the accepted value is "123 or the personalised one".
Permissions are exactly as entered — "عند تسجيل الدخول بالمستخدم الجديد تكون صلاحاته محددة كما تم إدخالها" (p.154). No default/auto-expansion is described.
No role-template is described. The document names two role types (مدير النظام، مشرف) in the caption text, but the form itself exposes only individual checkboxes — there is no "apply supervisor preset" button anywhere in pp.150–157. Roles. مدير النظام (system administrator) only — the password gate exists precisely to stop ordinary users from reaching this window (cf. L4‑4).

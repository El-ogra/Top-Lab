## 4. Module 5 — Specialized Profile Result Reports (backend only)

> **Execution-ready, owner-settled plan.** M-05 implements three binding decisions: Analyte is the exclusive owner of a current reference range and profile results freeze it; manual/profile charges use the one central financial service; authorised post-print profile amendments become active immediately and create immutable restricted audit records. Rendering remains M07/Presentation work.

### 4.1 Verified HEAD baseline and settled design

**Verified current facts (main 031a43e).** No Domain Analyte, Profile, profile/analyte link, profile-result range snapshot, or profile-amendment audit entity exists. ProfileResultItem.AnalyteName is a string, not a catalog identity. ReferenceRange belongs to Test; M04's PatientTestReferenceRangeSnapshot is one-to-one by PatientTestId. PatientAccountCalculator centrally aggregates persisted order prices/payment operations but lacks explicit manual/profile selection functions. PatientTest.MarkEntered(int, DateTime), Unreview(), and entered/reviewed/printed guards exist in src/TopLab.Domain/Results/PatientTest.cs and are reused unchanged. FakeApplicationDbContext already contains ProfileResultItems plus its Set/Add/Remove support and is reused unchanged.

**Settled technical design.**

- Add central Analyte, exactly one AnalyteReferenceRange aggregate per analyte, and typed age/sex bands beneath that aggregate. This preserves current clinical matching while making the analyte—not a profile or test—the only live range source.
- Add Profile, one-to-one with a specialised-profile Test, with immutable FixedPrice, and ProfileAnalyte many-to-many links. One analyte may appear in unlimited profiles.
- Replace profile-item name storage with required AnalyteId; add ProfileResultItemReferenceRangeSnapshot, keyed by ProfileResultItemId, retaining AnalyteId, selected-band fields, and capture time. Reports/reprints read only this snapshot.
- Map simple Test rows to an analyte and change the M04 individual-result/refresh path to resolve analyte bands then fill its existing PatientTestReferenceRangeSnapshot. Thus individual and profile results use the same analyte-owned historical-freeze rule.
- Add immutable ProfileResultAmendment. AmendProfileResultCommand updates the active item and adds the record in one relational SaveChangesAsync transaction. It never unprints, unreviews, versions, deletes, or replaces the item. It records item id, user, UTC time, old/new value/unit/flag, and optional reason.
- EDIT_RESULTS authorises amendment; existing PT_AUDIT_ACCESS authorises audit-log reading; absolute permission also passes the existing pipeline. No new permission seed is needed.
- Extend only PatientAccountCalculator with manual-selection and profile-selection charge entry points. Ordering persists their output in PatientTest.PriceAtOrderTime; all balances use a thin loader that delegates to PatientAccountCalculator.Balance. No M05 formula copy is permitted.

### 4.4 Slice 3 — Profile entry, report, print, and amendment

**Purpose:** deliver configured-analyte profile entry/reporting with frozen ranges, reused lifecycle, central balance loading, and post-print amendment.

**Changes:** Add Features/ProfileResults DTOs exposing AnalyteId, resolved name, active values/state, and frozen range display exclusively from ProfileResultItemReferenceRangeSnapshot. GetProfileEntryGrid loads configured profile analytes and current items. GetProfileReport reads only snapshots, supplies verified header/comment/print-setting fields, and never resolves current range.

SaveProfileResultsCommand accepts AnalyteId, requires a non-empty unique subset of configured analytes, is allowed only before review, replaces draft items, and captures each current analyte range in the same save. It maps comment to PatientTest.Notes; it must not delete printed/amended rows. Verify/unverify/print reuse MarkEntered, MarkReviewed, Unreview, and MarkPrinted. Print uses a thin loader delegating solely to PatientAccountCalculator.Balance and the existing per-user balance block.

Add AmendProfileResultCommand(ProfileResultItemId, ResultValue, Unit, Flag, Reason?), EDIT_RESULTS-gated. It permits printed/reviewed items, validates inputs, updates the active item, adds a complete immutable amendment row, and saves once. Add GetProfileResultAmendmentsQuery, PT_AUDIT_ACCESS-gated, ordered by timestamp/id. Normal users are denied by the pipeline; audit holders/absolute users may read.

**Validation:** tests prove configured-analyte-only entry, per-item snapshot capture, reprint unaffected by later range edits, lifecycle/print/balance delegation, printed-item amendment without unprint/new version, immediate active value, audit content/immutability/access control, and relational rollback of amendment plus audit on forced failure.

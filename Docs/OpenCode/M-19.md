## 1. Executive Summary

Module 19 delivers the four statistics surfaces as **gated, read-only projections** over the existing schema: patient counts classified by sex / referral entity / account type (with optional monthly breakdown), test and test-group counts, sent-out-sample statistics by period and destination lab (totals via the existing `SentOutAccountCalculator`), and user productivity from `PatientTest` attributions. **The physical schema is complete at HEAD — no migration is needed**; the S4 zero-drift gate proves it.

**Slicing:** 4 slices: S1 patient statistics → S2 test statistics → S3 sent-out + productivity statistics → S4 tests + zero-drift proof + close-out. Presentation slices do not exist in this plan because all UI work is out of scope.

---

## 2. Settled Business Rules (fixed — not open decisions)

1. **Zero storage change (SD-19-1).** No entity, column, table, index, configuration, or migration is created or modified.
2. **Gating (SD-19-2).** Every query implements `IAuthorizedRequest` with `STATISTICS`; denial returns the shared pipeline Forbidden message verbatim; `IsAbsolutePermission` bypasses.
3. **Periods (SD-19-3/5/6).** `DateOnly? From/To` → DateTime half-open UTC bounds (inclusive calendar days); default-today-UTC when omitted (M-11/M-16 precedent); validator rejects `From > To` («بداية الفترة يجب ألا تتجاوز نهايتها.»).
4. **Soft-delete (SD-19-3).** `IsDeleted` patients excluded from all patient/test statistics; audit visibility remains M-10's job.
5. **Single-sourced sent-out totals (SD-19-5).** `SentOutAccountCalculator` only (grep gate).
6. **Names via dictionaries (SD-19-3/5/6).** Referral-entity, lab, test-group, and user names resolved by dictionary lookups — no `Include` (M-16 S3 precedent); deleted/missing rows → raw id string (M-03 rule).

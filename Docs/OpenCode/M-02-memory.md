## Module Summary

Implements the patient registration and test-ordering backend (Domain + Application + Infrastructure; no Presentation). S1 adds Domain mutators and invariants — `Patient.SetPhoneNumbers` (replace-list), `AddMedicalCondition` / `RemoveMedicalCondition`, `IsDeleted` / `SoftDelete` / `Restore`, `EnsureNotDeleted` guards on `Update` / `AssignLabId`; `PatientTest.UpdateSampleFlags` (per-test, FR-M02-008 + settled OD-6); the `IsDeleted` column on `Patients` and the `(PatientId, IsSampleDrawn)` non-unique index on `PatientTests` plus the **only** new M-02 migration `20260907_AddPatientIsDeletedAndPatientTestSampleDrawnIndex.cs`. S2 builds the read surface: 6 read queries (`SearchPatients`, `GetPatientById`, `GetPatientVisitHistory`, `GetPatientTitles`, `GetMedicalConditionTypes`, `GetRegistrationCatalog` — the last one aggregates M12's `SearchTestCatalogQuery`, M22's `GetSystemSettingsQuery` for `DefaultAccountType` + `DisableAutoTitleInsertion` per settled OD-4, and M14's `ReferralNameResolver` for the two placeholders). S3 ships the write surface: 10 commands (`CreatePatient`, `UpdatePatient`, `SoftDeletePatient` with `DELETE_PATIENT`, `AddMedicalCondition` / `RemoveMedicalCondition`, `AddTestsToVisit` and `AddCustomGroupToVisit` **fully integrated against M-13's final surface** per §3.1 of the plan, no stub-then-gate split, both delegating to a shared pure `TestPriceResolver`; `RemoveTestFromVisit`, `UpdatePatientTestSampleFlags`, `ClearAllTests`) — all writes gated `ADD_EDIT_PATIENT` (id 1) except `SoftDeletePatient` (`DELETE_PATIENT` id 9), reusing the M17/M22 pattern (no new seed row, settled OD-8); S3 also adds the `FakeSender` test seam for M-02 → M-13 MediatR testing.

## 1. Executive Summary

S-00 closes the startup authentication gap and fixes the first-run administrator window's UX gaps. Today `MainWindow` opens with zero authentication (`App.xaml.cs:L98-L99` — unconditional `Show()` after the connection/migration/admin gates). Slice 1 creates the missing `LoginWindow`/`LoginViewModel` (reusing the fully implemented and tested `SignInCommand` pipeline) and makes login the single mandatory gate before `MainWindow` on both first-launch and subsequent-launch paths. Slice 2 adds four independent show/hide password toggles to `FirstRunAdminWindow` and a post-creation success confirmation whose wording matches the real next step (the Login window — no restart exists or is needed).

**Slicing:** 2 slices: S1 Login screen + startup gate → S2 FirstRunAdminWindow UX fixes. Sequencing rationale: S1 is the security-critical gap and carries the only composition-root change (largest blast radius, resolved first); S2's success-message wording and its "next screen is Login" verification only make sense once the login gate exists, so S2 depends on S1. Neither slice can be split further without shipping a half-wired state (a login window without the gate, or a gate without the window).

## 6. Open Questions (carried forward, with recommended defaults)

1. **Exact LoginWindow copy and layout.** No login UI has ever existed and no in-repo wording specification exists. Recommended default: mirror the FirstRunAdminWindow visual language (RTL, centered, fixed-size), title «تسجيل الدخول — Top-Lab», labels «اسم المستخدم»/«كلمة المرور», buttons «دخول»/«خروج», and one independent show/hide toggle on the password field for consistency with S2.
2. **Authentication error wording.** The handler returns fixed Arabic strings («اسم المستخدم أو كلمة المرور غير صحيحة» / «المستخدم غير مفعل», `SignInCommandHandler.cs:L11-L12`). Recommended default: present verbatim via `ResultErrorPresenter` (the established idiom), preserving the deliberate ambiguity between "unknown user" and "wrong password".
3. **Session lifecycle during MainWindow lifetime (sign-out / lock / switch user).** `SignOutCommand`/`LockWorkstationCommand` are implemented but have no presentation caller (only test callers). Recommended default: out of scope — keep "close MainWindow = exit application"; wiring sign-out/lock is a separate later task.
4. **Secondary-password field toggles in FirstRunAdminWindow.** The requirement names only "password" and "confirm-password", but the window has four secret fields. **Settled by this plan (Audit C-2): apply toggles to all four fields** (uniform UX, negligible cost).

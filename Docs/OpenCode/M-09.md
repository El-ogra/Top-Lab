## 1. Executive Summary

Module 09 delivers the aggregation surface for the delivery handover: the list of patients with undelivered results in a period (FR-M09-001), the per-patient delivery grid **with the price column** (`PatientTest.PriceAtOrderTime`), the financial position at handover (paid / remaining-to-patient / remaining-to-lab — FR-M09-002), and the composite `DeliverWithSettlement` command (FR-M09-003/004). At HEAD, the atomic logic already exists: `MarkResultDelivered` (Domain guard + Application command), the BR-07 print-time balance gate (M-04/M-06), and the account calculator (M-03). What does not exist is `Features/ResultDelivery/` (verified: folder list at HEAD) — the queries and the composite command are the module's new core.

The settled rules keep the architecture consistent: **no balance gate on delivery itself** (the block is print-time only, per the code/ADR decision embedded in `MarkResultDeliveredCommandHandler`); settlement is a `Payment` by default with a "خلاص" path reusing `SettleAccountInFull`; and the financial position is derived from the sign of `Balance` only. **No migration is needed** — every column (`DeliveredByUserId`, `DeliveredAtUtc`, `PriceAtOrderTime`, payment tables) exists at HEAD; S3 runs the zero-drift proof.

**Slicing:** 3 slices: S1 Application read surface → S2 Application composite command → S3 tests + Infrastructure proof + close-out. Presentation slices do not exist in this plan because all UI work is out of scope.

## 2. Settled Business Rules (fixed — not open decisions)

These rules are settled facts encoded directly in the slices below. They are not alternatives and must not be reopened:

1. **Delivery requires printed.** Every line in `DeliverWithSettlement` must satisfy `IsPrinted == true`; the Domain guard `MarkDelivered` is authoritative and its rejection is translated via `DomainFailureTranslator` to the Arabic message (pattern: `MarkResultDeliveredCommandHandler:46-53`).
2. **No balance gate on delivery.** Delivery is the physical handover (BR-08); the balance block lives before printing for delivery (BR-07, FR-M09-003) and is **not** re-applied at delivery time. Delivery proceeds even with a remaining balance; the account is shown for optional settlement.
3. **Settlement semantics (OD-09-B).** `settleAmount > 0` records a `Payment` operation through M-03's existing logic (no formula duplication — the D5 principle, same as `BalanceProbe`). A "خلاص" (full settlement) choice delegates to the existing `SettleAccountInFull` logic, which rejects with `Error.Conflict("لا يوجد رصيد مستحق للتسوية.")` when balance ≤ 0 and creates a `FullSettlement` operation with `Amount = balance`.
4. **Sign-derived position (OD-09-C).** Remaining-to-lab = `Balance > 0` amount; remaining-to-patient (credit) = `Balance < 0` absolute amount; both zero when `Balance == 0`. Derived from `PatientAccountCalculator.Balance` exclusively.
5. **Delivery audit.** Every delivered line records `DeliveredByUserId = ICurrentUserService.UserId` and `DeliveredAtUtc = IDateTimeProvider.UtcNow` (FR-M09-004).
6. **Single operational gate (OD-09-A).** `GetUndeliveredResults`, `GetDeliveryGrid`, `GetDeliveryAccount`, and `DeliverWithSettlement` all carry `IAuthorizedRequest` with `RequiredPermissionCode => "DELIVER_RESULTS"` (seeded id=6; reuse of `ResultsEntryAccessPolicy.DeliverResults`). No new permission code under any outcome.
7. **List semantics.** The undelivered list shows non-deleted patients registered in the period who have **any** `PatientTest.IsDelivered == false`, with the per-visit aggregated status (finished/unfinished) computed by `PatientStatusCalculator` — matching M-08's calculator verbatim.
8. **Grid price column.** The delivery grid includes `Price` sourced from `PatientTest.PriceAtOrderTime` (frozen at order time) — never a live catalog price (FR-M09-001).

## 2. Settled Business Rules (fixed — not open decisions)

Derived from verified code + reference text; encoded directly in the slices:

1. **No new migration.** All tables/columns/FKs needed by M15 already exist from the F5 baseline (§1.3, line-level verified); a model-vs-snapshot zero-drift gate runs in the Infrastructure slice and any discovered drift (there should be none) triggers plan revision, not silent migration.
2. **Permission gate.** All M15 write commands carry `IAuthorizedRequest` with `RequiredPermissionCode => "EDIT_SYSTEM_SETTINGS"`; all read queries are open (M12/M14 precedent, verified).
3. **Result pattern.** No exceptions cross the Application boundary for expected failures; domain `ArgumentException`s are translated to Arabic `Error.Validation` via a feature-local `DomainFailureTranslator` (M14 precedent, read in full); expected lookup misses → `Error.NotFound`; reference-blocked deletes → `Error.Conflict`; duplicate-reference races at save time → the `IsReferenceConflict(ex)` catch (M14 `DeleteExternalEntityCommandHandler` precedent) mapped to `Error.Conflict`.
4. **Name/text rules.** `Antibiotic.Name`: required, trimmed, max 150 (column length, verified). Flags `IsPregnancyFlagged` and `IsChildrenFlagged` are freely editable through `Antibiotic.Update` (the verified D4-a, owner-approved rule).
5. **Referential integrity at the Application layer.** Handlers existence-check `TestId` and `AntibioticId` before item operations; duplicate attachment (same composite key) → `Error.Conflict`. Because no DB FK exists from `CultureAntibioticAttachment` to either `Test` or `Antibiotic` (verified), the Application layer is the sole enforcement point for attach integrity.
6. **Antibiotic delete guard.** Blocked (`Conflict`) when (a) the antibiotic is attached to any culture (`CultureAntibioticAttachment` rows exist — **application-level check required because no DB FK exists**, verified), or (b) referenced by `CultureAntibioticResult` (DB-level Restrict, verified — M06 data cannot exist yet; the check is implemented anyway for forward safety), plus a save-time `IsReferenceConflict` catch mapping to the same Conflict.
7. **Culture-attachment integrity.** Attach requires: target `Test` exists **and `IsCultureType == true`** (a plain test must not receive antibiotics — the flag exists precisely for this; verified to exist and to be create-time-only settable), antibiotic exists, no duplicate attachment (composite key) → `Conflict`. Detach removes the row; orphan attachments are prevented by the antibiotic delete-guard (rule 6) and by the absence of test hard-delete at this commit (verified: M12 ships Deactivate/Reactivate only — no `DeleteTest` command exists). The `IsCultureType` flag itself is set through M12's `CreateTestCommand` (verified: the command carries `IsCultureType` and the handler passes it to `Test.Create`) — M15 does **not** reopen catalog CRUD (delegation, §2.1).
8. **Flag semantics (BR-12 contract).** M15 stores both flags and ships a **pure static resolver** (static-class precedent verified: `ReferralNameResolver` in M14's feature Common folder; per its placement the resolver ships in the Application feature's Common folder, not the Domain layer): given an antibiotic's flags and a patient context (`isPregnancyIndicated: bool`, `isChildUnder12: bool`), return whether the antibiotic is displayable. Rule: unflagged → always displayable; `PregnancyFlagged` → displayable only when pregnancy indicated; `ChildrenFlagged` → displayable only when child; when **both** flags are set → displayable when **either** condition holds (**union semantics — confirmed rule D5-a, owner-approved**). The **12-year threshold is a named constant** in the resolver (`ChildAgeThresholdYears = 12`, per the reference text §9-3 and PRD FR-M15-004); computing `isChildUnder12` from the patient's `AgeValue`/`AgeUnit` pair is M06's job (any Day/Month age is under 12 years; Year requires `AgeValue < 12` — no unit conversion exists per BR-04, verified) — M15 takes it as an input, keeping the resolver pure and patient-agnostic.
9. **Read surface completeness.** For each of the two managed concepts (antibiotics, attachments): list query + detail query, with the reference-shown shapes — culture-attachment listing includes the **attached count** (explicitly shown in the reference §9-3: "وعددها"); antibiotic list is global, optional search.

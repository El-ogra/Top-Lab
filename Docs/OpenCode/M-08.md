## 6. Module 8 — Patient Search, Lab ID & Visit History (backend only)

> Self-contained plan. **All of this module's rules are settled requirements:** patient lists display the patient's **aggregate status icon computed by the seven-state precedence rule of §8** (FR-M08-007 — so this module exposes the computed status, not raw flags; the calculator is delivered in full per the settled PRD §8.2/§8.3 model — inlined below); the per-visit balance rollup (the settled formula — inlined below); Lab ID vs Patient ID distinction and the code-printing setting (BR-02/§9; FR-M08-005/006/008); search by any stored phone number (BR-03/FR-M08-002); result-state filters not-entered / not-reviewed / not-printed / not-delivered (FR-M08-004); no `PatientTest.IsDeleted` (Data Model §6.1/§2 + ADR-0018). Feature folder: `PatientSearch`.

### 6.1 Module 8 context — what exists and what is assumed (inlined)

- **Existing at `70f145e` (re-verified):** `Patient` full shape: `LabId?` (strongly-typed `LabId : StronglyTypedId<string>`, stored ≤30, indexed), `Title?` (≤50), `FullName` (≤200, indexed), `Sex`, `AgeValue`, `AgeUnit`, `NationalId?` (≤30, indexed), `Address?` (≤300), `TreatingDoctorId?`, `ReferralEntityId?`, `AccountType { Individual=0, LabToLab=1, Contracts=2, Vip=3, Free=4 }` (tinyint), `IsVip`, `RegistrationDateUtc` (datetime2, indexed), `PickupDateUtc?`, `IsFastingIndicated`, `FastingHours?`, `RecentContrastImaging`, `Notes?` (≤1000); `PatientPhoneNumber` (`PhoneNumber` indexed, `SortOrder`, `PatientId` indexed); `PatientMedicalCondition` join; `MedicalConditionType` (`Name`, `Category`); `PatientTitle`; `PatientTest` with all lifecycle flags (`ResultValue?`, `ResultFlag?`, `EnteredAtUtc?`, `IsReviewed`, `IsPrinted`, `PrintCount`, `IsDelivered`, etc.). `ReportSettings.HistorySortMode { ByLabCode=0, ByPatientName=1 }` + `HistoryAutoDisplayEnabled` (re-verified; writable via M22's shipped `UpdateReportSettingsCommand`; FR-M22-015). `SystemSettings.EnablePatientNameSearchAssist` + `PrintLabIdInsteadOfPatientId` (re-verified; FR-M22-008). **One-row-per-visit:** `Patient`'s XML comment (re-verified verbatim): "One row per visit (registration). LabId is shared grouping value across visits." — **this is the verified visit-grouping rule: visits of one physical patient are the `Patient` rows sharing the same `LabId`** (PRD §9: the Lab ID aggregates visits and drives history; the Patient ID identifies the registration record).
- **The settled aggregate-status dependency (inlined in full):** `PatientStatusCalculator.Calculate(Patient, IReadOnlyList<PatientTest>, decimal balance)` → `PatientAggregateStatus` (`S1=1…S7=7`) implementing PRD §8.2/§8.3 verbatim: the seven statuses are **S1 New** (newly registered; no result entered for any requested analysis), **S2** (one or more results not yet entered), **S3** (entered but not reviewed), **S4** (entered and reviewed but not printed), **S5** (printed but not delivered), **S6** (all delivered, outstanding balance), **S7** (entered, printed, delivered, settled). Each analysis maps to a stage by its earliest outstanding action (1 entry-pending→S2 · 2 review-pending→S3 · 3 print-pending→S4 · 4 delivery-pending→S5 · 5 settlement-pending→S6 · 6 complete→S7); **PatientStatus = state(min over all per-analysis stages AND the account condition)**; the account condition is evaluated only when no analysis is at stages 1–4; S1 applies iff no analysis has `EnteredAtUtc` set AND `RegistrationDateUtc` falls on the current UTC day (pinned boundary); binding worked example {3,4,1}→S2. Stateless Domain Service, never stored (ADR-0015). This module calls the Domain Service directly (Domain → Domain is legal; no cross-feature Application reference). *First-shipper rule (verbatim): if `PatientStatusCalculator` still throws at this module's execution time, this module's Slice 1 implements the §8.2/§8.3 rule inside the calculator itself with exactly the pinned semantics above (it is Domain code; added under the first-shipper contingency and the collision resolution is recorded in the close-out ADR; a later merger verifies presence instead of adding).*
- **Assumed from M02 (inlined):** `Patient.IsDeleted` + index exist; M02's `SearchPatientsQuery` (name/national-id/LabId/phone match, `!IsDeleted`, paged 50/500) and `GetPatientVisitHistoryQuery` exist in the `PatientRegistration` feature; the fake gains `PatientPhoneNumber`, `PatientMedicalCondition`, `PatientTitle`, `MedicalConditionType` lists. **This module's relationship to those (stated fully inside this plan):** M02's queries are registration-scoped (small summaries for the registration screen). This module is the dedicated search/history surface (FR-M08-001…008): richer DTOs (per-visit lifecycle rollup, aggregate status, account balance, phone list), Lab-ID-centric lookup, and history-viewer settings echo (`HistorySortMode`, `HistoryAutoDisplayEnabled`). This module does NOT call or import M02's handlers/DTOs; it re-queries the same tables with its own projections (independence rule satisfied by construction). The overlap is deliberate and documented in this module's ADR.
- **Balance formula (settled — inlined in full, per independence):** `TotalCharged = Σ PatientTest.PriceAtOrderTime + Σ (PaymentOperation.Amount where !IsVoided && IsExtraCharge)`; `TotalPaid = Σ (PaymentOperation.Amount + coalesce(DiscountAmount, 0) where !IsVoided && !IsExtraCharge)`; `Balance = TotalCharged − TotalPaid` (negative = credit; `Correction` = credit on paid side; `FullSettlement` = ordinary payment; voided ignored). This module ships its own private `Common/BalanceProbe.cs`. Reference corroboration: `RLS_Learn.pdf` §1-3 shows per-visit account ("المدفوع والباقي") alongside results state at delivery/history time.

### 6.2 Module 8, Slice 1 — Application read surface: global search, Lab-ID lookup, visit history with rollup

*(This module introduces **no Domain changes and no migration** — all read projections over existing + assumed-M02 schema (the contingent calculator implementation of the context section is the only possible Domain touch). The slice sequence is therefore **S1 read surface → S2 settings-dependency verification → S3 Infrastructure proof + close-out**. Execution hygiene (one line): the settled baseline is no `PatientTest.IsDeleted`; *if* execution finds M02 deviated and added the flag, add `&& !pt.IsDeleted` to this module's named queries — the test-count join in `SearchPatientsGlobal`, the rollups in `GetPatientByLabId`/`GetVisitHistory`, and the test lines in `GetVisitDetail` — and record the drift.)*

- **Files / classes to add or change.**
  - **Add** `Features/PatientSearch/Common/PatientSearchDtos.cs`:
    ```csharp
    public sealed record PatientSearchHitDto(int PatientId, string? LabId, string FullName,
        string? Title, string Sex, int AgeValue, string AgeUnit, string? NationalId,
        IReadOnlyList<string> PhoneNumbers, string AccountType, bool IsVip,
    ```

    (Per-visit `AggregateStatus` is computed by the settled `PatientStatusCalculator` over the visit's own tests + the visit's own balance — the per-registration status, satisfying FR-M08-007's "patient lists shall display the aggregate status icon computed by the seven-state precedence rule of §8". Raw lifecycle counts/flags are retained alongside for the history view. Enums projected as name strings for display-ready output, same convention note as the billing module.)
  - **Add** `Common/BalanceProbe.cs` (private copy of the inlined formula).
  - **Add** `Queries/SearchPatientsGlobal/SearchPatientsGlobalQuery.cs` (+Handler, +Validator) — `(string? Text, int Page = 1, int PageSize = 50)`. Match semantics (FR-M08-001/002): `Text` empty → most recent registrations (the "open the screen" behavior); else case-insensitive substring on `FullName`, OR exact match on `LabId` or `NationalId` (trimmed), OR substring on any `PatientPhoneNumber.PhoneNumber` (BR-03: search by **any** stored number retrieves the record); always `!IsDeleted`. Honors `SystemSettings.EnablePatientNameSearchAssist` (FR-M08-003/FR-M22-008) — when false, name substring matching is disabled and only LabId/NationalId/phone matches run (the setting's literal reading; recorded in the ADR). Ordered by `RegistrationDateUtc desc`. `AggregateStatus` computed per hit via the settled calculator (balance via `BalanceProbe`). Validator: `Text` ≤ 200, Page ≥ 1, PageSize ≤ 500 (M02 precedent). No gate.
  - **Add** `Queries/GetPatientByLabId/GetPatientByLabIdQuery.cs` (+Handler, +Validator) — `(string LabId)` → the **latest** visit (`Patient` row, max `RegistrationDateUtc`) for that LabId + the `VisitHistoryDto` rollup (all non-deleted visits sharing the LabId — FR-M08-006: searching by Lab ID displays **all of the patient's visits** with their dates). NotFound (`"لا يوجد مريض بهذا الكود."`) when no non-deleted row has the LabId. Validator: non-empty, ≤30 chars (verified `LabId` storage length).
  - **Add** `Queries/GetVisitHistory/GetVisitHistoryQuery.cs` (+Handler, +Validator) — `(int PatientId)`: loads the row (`Error.NotFound("المريض غير موجود.")` on missing or `IsDeleted`); when its `LabId` is null, the history is the single visit (stated rule); otherwise loads **all non-deleted `Patient` rows sharing the `LabId`**; per visit computes the test rollup (counts over that visit's `PatientTest` rows: `ResultsEntered` = count `EnteredAtUtc != null`; the four `All*` booleans are true when `TestCount > 0` and the respective count equals `TestCount` — an empty visit reports all-false, stated rule), the aggregate status (settled calculator), and balance (BalanceProbe); ordering: visits ordered by `RegistrationDateUtc desc` always (within one LabId the sort mode has no cross-patient effect); the `HistorySortMode`/`HistoryAutoDisplayEnabled` values are **echoed** in the DTO for the future screen (the setting's real cross-patient effect applies to merged multi-patient views outside this query — documented in code and ADR). No gate.
  - **Add** `Queries/GetVisitDetail/GetVisitDetailQuery.cs` (+Handler, +Validator) — full `VisitDetailDto`; medical-condition names resolved via the join + `MedicalConditionTypes`; phone numbers ordered by `SortOrder`; test lines ordered by `PatientTestId`. NotFound on missing/soft-deleted. No gate.
  - **Fake:** extend **only if M02's additions are absent** (contingency): `PatientPhoneNumber`, `PatientMedicalCondition`, `MedicalConditionType`, `PatientTitle` lists.
  - **Add** handler tests — global search (each match channel; search-assist off disables name match; soft-deleted excluded; pagination; empty-text recency; aggregate status present and correct for a mixed-stage patient), LabId lookup (latest visit chosen; unknown → NotFound; soft-deleted latest visit skipped to the next non-deleted — stated rule, tested), history (multi-visit grouping by shared LabId; null-LabId single-visit; rollup counts; empty-visit all-false; per-visit status via the calculator; balance from the inlined formula with the worked example prices 100+50, extra charge 20, payment 80 with discount 10, voided payment 999 ⇒ Charged 170, Paid 90, Balance 80; soft-deleted sibling visits excluded; settings echoed), detail (condition names resolved; phone ordering by `SortOrder`; test lines by id).

### 6.7 Module 8 — Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Duplicate search surfaces (M02 vs this module) confuse future maintainers | Deliberate-overlap ADR records which screen consumes which surface; naming distinguishes them (`SearchPatients` vs `SearchPatientsGlobal`). |
| LabId reused across unrelated patients (data-quality) | The one-row-per-visit grouping rule is the verified Domain contract; the ADR quotes it verbatim; no de-duplication logic is invented. |

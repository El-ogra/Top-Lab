## 1. Executive Summary

Module 18 delivers attendance & time tracking: guards on the existing factory-light `AttendanceRecord` entity, the single-sourced `AttendanceCalculator`, four self-service write commands (check-in with computed lateness, break start/end, check-out with computed overtime), and two manager-only reads (per-period records, per-user overtime/lateness summary). The **physical schema is complete at HEAD — no migration is needed**; the S4 zero-drift gate proves it.

**Slicing:** 4 slices: S1 Domain → S2 Application writes → S3 Application reads → S4 tests + Infrastructure proof + close-out. Presentation slices do not exist in this plan because all UI work is out of scope.

## 2. Settled Business Rules (fixed — not open decisions)

1. **Zero storage change (SD-18-1).** No migration, no column, no index, no configuration edit.
2. **Self-service writes (SD-18-2).** All four commands record for `_currentUser.UserId` only; unauthenticated (`IsAuthenticated == false`) → `Error.Forbidden` shared message. A user can never record attendance for another user.
3. **Manager-only reads (SD-18-3).** Both queries: handler-level `_currentUser.IsAbsolutePermission` check, else `Error.Forbidden("أنت لا تملك الصلاحية لهذا العمل راجع مدير النظام")`.
4. **Computation (SD-18-4/7).** Lateness at check-in and overtime at check-out computed once via `AttendanceCalculator` against `User.WorkStartTime`/`WorkEndTime`; worked minutes exclude the recorded break span. Missing configuration → null lateness/overtime (never an error).
5. **Single open record (SD-18-5).** Check-in rejected while an open record exists.
6. **Break sequencing (SD-18-6).** Domain guards authoritative; validators mirror textually.
7. **No edit/delete (SD-18-9).** No modification path exists anywhere in the module.

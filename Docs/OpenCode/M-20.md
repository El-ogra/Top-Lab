## 1. Executive Summary

Module 20 delivers the Accounts backend surface as **gated computed aggregates plus the cash-movement write surface** over the already-complete physical schema: the ten-figure cash-drawer inventory over daily/weekly/monthly/annual/custom periods (FR-M20-001/002/003), per-element inventories for user / referral entity / treating doctor / account type / sent-out samples with the four report types (FR-M20-004), the per-patient detail drill-down (FR-M20-005), cash disbursement/deposit commands persisting `CashMovement` rows, and the company/delegate per-entity account tracking (FR-M20-006). **The physical schema is complete at HEAD — no migration is needed in any slice**; every slice runs the zero-drift gate and S4 proves it solution-wide.

**Slicing:** 4 slices: S1 `CashMovement` domain guards + tests → S2 inventory read surface (drawer inventory + per-element + detail) → S3 cash write commands + company/delegate accounts + authorization tests → S4 tests roll-up + zero-drift proof + close-out. Presentation slices do not exist in this plan because all UI work is out of scope.

## 2. Settled Business Rules (fixed — not open decisions)

1. **Zero schema change (SD-20-1/SD-20-2).** No entity, column, table, index, configuration, or migration is created or modified. S1 changes only `CashMovement.Create` *behavior* (guards); the mapped property set is identical.
2. **Gating (SD-20-3).** Every command and query implements `IAuthorizedRequest` with `CASH_DISBURSE_DEPOSIT`; denial returns the shared pipeline Forbidden message verbatim; `IsAbsolutePermission` bypasses. No second gate inside handlers. `PermissionConfiguration.cs` untouched.
3. **Periods (SD-20-6).** Uniform half-open UTC bounds, inclusive calendar days, default-today, frozen inverted-period message «بداية الفترة يجب ألا تتجاوز نهايتها.».
4. **Soft-delete (SD-20-7).** `IsDeleted` patients excluded from all inventory figures.
5. **Single-sourced formulas (SD-20-5/SD-20-10).** `PatientAccountCalculator` / `SentOutAccountCalculator` only (grep gate); commission, safe-cash and net-profit formulas fixed by SD-20-8/SD-20-10.
6. **Names via dictionaries (SD-20-11).** User/entity names resolved by dictionary lookups — no `Include`; deleted/missing rows → raw id string (M-03 rule).
7. **Single branch (BR-09).** No branch dimension anywhere in any query.

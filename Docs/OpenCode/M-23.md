## 1. Executive Summary

Module 23 delivers the Utilities backend surface: three pure Domain computation services (measurement-unit converter, arithmetic calculator, stopwatch math) with thin ungated Application queries, a read-only Test Library catalog query, and two workstation-local JSON-backed lists (Requirements & Purchases, Phone Book) behind Application ports implemented in Infrastructure exactly on the `ILabPrintTextStore` precedent. **No business-schema change and no migration in any slice** — the only persistence is workstation-local JSON files, which the database migration tooling never sees; every slice runs the zero-drift gate and S4 proves it solution-wide.

**Slicing:** 4 slices: S1 Domain computation services + tests → S2 Application computation queries + Test Library query + tests → S3 JSON list stores (ports, commands/queries, Infrastructure implementations, DI) + tests → S4 tests roll-up + zero-drift proof + close-out. Presentation slices do not exist in this plan because all UI work is out of scope.

## 2. Settled Business Rules (fixed — not open decisions)

1. **Zero business-schema change (SD-23-1/SD-23-2).** No entity, column, table, index, configuration, or EF migration is created or modified. List persistence is workstation-local JSON only.
2. **Gating (SD-23-3).** Every member is ungated, mirroring `CheckDatabaseConnectivityQuery`; `PermissionConfiguration.cs` untouched.
3. **Fail-closed computation (SD-23-8/SD-23-9/SD-23-10).** Unknown unit pair, malformed expression, division by zero, and inverted stopwatch bounds are rejected explicitly — never silently approximated.
4. **Phone-book separation (SD-23-11).** The Tools Phone Book never references `Patient` or patient phone numbers (FR-M23-002 binding).
5. **Single branch (BR-09).** Not applicable to computations; the JSON stores are per-workstation by design (ADR-0021 locality rationale).

## 7. Module 11 — Work Sheets (backend only)

> Self-contained plan. **All of this module's rules are settled requirements:** worksheets are **period/range-based** — every worksheet mode operates over "a specified period" (FR-M11-001/002/003), the Work Sheets screen carries a period picker (UI Blueprint S-33), and worksheet printouts are period outputs (FR-OUT-07); a day-only design is non-conforming. The **period test-count classification ships in this module** (FR-M11-004 "a classification of a period's tests showing how many times each test was performed"; PRD §1.2 item 8 included scope; PRD §4 module map + Module Dependency Map §3 "frequency classification" under M11; FR-OUT-07 "test-frequency classification printouts"; S-33 "classification view"; Master Tracking §6.2 M11 block). Worksheet generation is gated on `PRINT_WORKSHEET` (FR-M17-004 item 8; the classification lives inside the M11 screen per S-33, so it shares the worksheet grant — not `STATISTICS`). Tube-barcode content is pinned for the future renderer (Reporting §7: Code 128; `PatientId` or `LabId` per `SystemSettings.PrintLabIdInsteadOfPatientId`; date/time on tube barcode per `PrintDateTimeOnTubeBarcode`). No `PatientTest.IsDeleted` (Data Model §6.1/§2 + ADR-0018). **The worksheet-line identifier (settled by the owner): each worksheet line carries the internal visit/test identifier `PatientTestId` together with the `LabId` — the scannable identity pair — with `Test.Barcode` kept as the test classifier and the barcode/identifier system settings echoed for the future renderer.** **The worksheet default period and boundary semantics (settled by the owner): the system supports a selectable date range (`DateOnly? From` / `DateOnly? To`), both defaulting to the current day in UTC when unspecified; `From > To` → Validation; bounds are inclusive on UTC calendar days.** Feature folder: `WorkSheets`.

### 7.1 Module 11 context — what exists and what is assumed (inlined)

Permission `PRINT_WORKSHEET` (id 8) seeded. `SystemSettings.PrintFileExternalBarcode`, `PrintDateTimeOnTubeBarcode`, `PrintLabIdInsteadOfPatientId` exist (re-verified) — consumed below.
- **Assumed from M02/M21 (inlined):** `Patient.IsDeleted`; `PatientTest.UpdateSampleFlags`; M21's draw state (`IsSampleDrawn`/`SampleDrawnAtUtc`) maintained; M02's registration timestamps (`Patient.RegistrationDateUtc`).
- **Worksheet semantics (defined fully inside this plan — no external reference):** a worksheet is a **printable list of pending lab work** = `PatientTest` rows for a chosen **period** (`DateOnly? From`/`To` — range-capable per the settled period requirement; **settled by the owner: both default to the current day in UTC when unspecified, `From > To` → Validation, bounds inclusive on UTC calendar days**) whose sample should be in the lab (`!IsTakenOutsideLab`), grouped either (a) by a saved `WorkGroupLog` (FR-M11-003 — the lab's named bench sheets) or (b) by `TestGroup` / explicit test selection (FR-M11-002 — "a single test or a selected group of tests"), showing patient name/LabId (FR-M11-001 "by their names or their codes"), test name/code, the line identifier pair (**settled by the owner: `PatientTestId` + `LabId`**), sample-drawn state, and result-entry state. The patient-based worksheet ("by patient names") is the same line set transposed per patient — covered by ordering the sections' lines by patient. The **period test-count classification** (FR-M11-004) ships as its own query in this module (next slice). A separate `MarkWorkSheetPrinted` audit command is **not** shipped (no print-tracking columns exist for worksheets and adding them is out of the verified schema — the `PRINT_WORKSHEET` permission is enforced on the generation queries instead, since generating = printing here; stated rule).

|---|---|
| UTC-day boundary shifts late-evening registrations to "yesterday's" sheet (Egypt UTC+2/+3) | The settled default/boundary semantics (UTC days, inclusive, default today) record the caveat in the ADR; a lab-timezone setting is flagged as future work (no such setting exists in the verified `SystemSettings`). |
